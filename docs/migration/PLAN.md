# Sub2API 组织仓库迁移方案

日期：2026-10-02。状态：方案文档，尚未实施代码迁移、推送、数据库变更或部署。

## 1. 目标与范围

以 `https://github.com/baibaiAi001/sub2api.git` 为新的组织仓库，以其 fork 的 `ranxi2001/sub2api` 为后续功能上游，只迁入当前站点的四项定制：**图片生成工作台、首页、教程页面、充值提醒**。

采用“新 fork 基线 + 四项独立 Extension”的方式。不要把旧 `custom/main` 整体合并到新仓库，也不要仅替换线上镜像，否则会同时引入旧定制或丢失需要保留的功能。目标交付物应为组织仓库自行构建的镜像；直接使用 ranxi2001 的预构建镜像不包含这四项本地定制。

“其他定制移除”指当前站点自行添加的扩展、覆盖逻辑及其运行服务；新 fork 原生能力作为基线保留，不因名称相似而误删。例如 fork 自带的 Pelican 测智与旧站本地 Pelican 图库是不同实现，不自动迁移旧图库数据，也不自动启用 fork 的测试计划。旧插件包不自动安装或启用。

## 3. 四项保留功能及改造要求

### 3.1 图片生成工作台

迁入：

- `frontend/src/features/image-generation/`
- `backend/internal/extensions/image-generation/`
- `/image-generation`、`/image-generation/settings` 页面及必要的 API、路由注册、配置、国际化和侧边栏入口。

保留文生图、图生图、提示词优化、尺寸/数量选择、生成结果预览下载和现有浏览器缓存行为。保留数据库中 `extension.image_generation.user.*` 设置，继续按当前登录用户读取；保留已有分组、模型和 API Key 引用，但在 fork 的权限与模型规则下重新校验。

使用 fork 的正式网关、鉴权和计费接口，不复制旧网关实现。不要将旧 `handler/wire.go`、`router.go` 或生成文件整体覆盖到 fork；只迁入必要组装，按目标仓库命令重新生成 Wire。

### 3.2 首页

迁入 `frontend/src/features/home-showcase/`、所需图片资源、国际化文案，以及 `HomeView.vue` 的最小挂载改动。保留当前品牌呈现、布局、站点名称/Logo 配置读取、注册登录和教程入口。

已发现首页多处链接指向 `/model-plaza`。由于自定义模型广场不再保留，应移除依赖旧广场的价格区块和链接，或在确认 fork 原生价格入口可用后改接该入口。不得为保留首页而再次迁入整个旧模型广场。

首页中第三方工具介绍可以保留为外部文档/官网链接；DeepSeek Harness、CC Switch 等旧站一键安装、启动和配置行为全部移除。只保留实际需要的资源，不能留下按钮指向已撤掉的内部 API。

### 3.3 教程页面

迁入：

- `frontend/src/features/tutorials/`
- `backend/internal/extensions/tutorials/`
- `tutorial_videos` 配置解析、管理接口、公开视频列表、封面上传/读取、播放计数及 `/tutorials` 路由。

保留原 `224_tutorial_video_play_counts.sql` 文件名和原始内容，不重编号、不改 checksum；将它作为保留扩展的历史迁移一并纳入新版本，确保已有数据库和全新安装都能工作。

保留 `tutorial_video_play_counts` 数据、`tutorial_videos` 设置和 `/app/data/tutorial-covers` 文件。教程文档链接继续使用当前站点配置/既有地址，避免换成 fork 作者站点。上传接口必须保持管理员权限，公开接口只暴露已发布教程，不返回内部设置。

### 3.4 充值提醒

迁入 `frontend/src/features/recharge-notice/`，在 fork 的 `PaymentView.vue` 以最小改动挂载提醒。保留客服信息和人工优惠说明，充值比例从支付接口的实际倍率读取。

旧定制还将 `backend/internal/service/payment_amounts.go` 的默认充值倍率从 1 改为 10。此次**不继续复制硬编码的全局默认值覆盖**；正式迁移前读取当前有效商业配置，若站点实际规则为 1 元兑换 10 美元余额，则通过 fork 支持的持久化设置明确保留该值，并用报价/订单验收证明到账金额一致。不能因撤掉旧代码而把实际充值比例意外变成 1。

fork 自带在线充值赠金/折扣阶梯，与现有“人工办理优惠、在线充值不享受”文案可能冲突。初次迁移保留当前实际优惠政策，原生在线阶梯保持关闭；未来启用时同步调整文案和金额验收，避免重复优惠。

## 4. 移除清单与数据退出策略

| 旧定制 | 代码/运行行为处理 | 历史数据处理 |
| --- | --- | --- |
| 自定义模型广场 | 不迁入 `features/model-plaza`，不迁入分组驱动的旧 `model_plaza_service.go` 覆盖；使用 fork 原生行为 | 保留核心分组价卡和模型配置，它们仍用于业务，不作为扩展垃圾删除 |
| DeepSeek Harness | 不迁入前后端扩展、短时票据 API 和 Helper 集成 | 旧开关停用；相关设置/文件先归档 |
| 本地工具入口 | 不迁入 `features/local-tools`、后端 local-tools、站点 Helper 注册和下载入口 | 客户端已安装工具不远程卸载；服务端不再提供旧集成 |
| 本地 Pelican 图库 | 不迁入 `extensions/pelican`、`features/pelican`、启动任务、配置和图库路由 | `pelican_config/runs/artifacts/gallery_settings` 及磁盘作品先归档保留；不导入 fork 的测智表 |
| STATE 外接采集 | 保持监控/采集/调度服务禁用，移除运行依赖和页面注入 | 旧票据、日志、配置先归档；不自动恢复服务 |
| 其他旧定制补丁 | 不整体继承旧分支；逐文件确认，四项保留功能以外的差异不迁入 | 不删除账号、用户、余额、订阅、订单、用量和核心设置 |

“移除功能”首先指代码、入口和自动任务退出。首次切换不做 DROP TABLE、不删已执行迁移记录、不批量删除设置或数据目录。旧 Pelican 的六条 `241_local_*` 至 `246_local_*` 迁移留在旧仓库与备份中，新程序无需执行它们；数据库已存在的记录与表暂存，源码执行器对额外历史记录的处理仍须在恢复副本上验证。

待上线稳定并确认归档可恢复后，再单独制定物理清理清单和新增清理迁移。不能把删除历史数据当成当前“移除定制功能”的默认授权。清理旧 `state-reuse/admin.env` 等文件前，须检查其他独立服务是否还引用，防止误伤共享配置。

## 5. 新仓库组织与发布

建议在独立目录建立新 checkout，例如 `/home/sub2api/migration/org-sub2api`，保留旧仓库原状供对照和回滚。

- `origin`：新组织仓库 `baibaiAi001/sub2api`。
- `upstream`：功能上游 `ranxi2001/sub2api`。
- `production`：保持新 fork 的干净上游基线。
- `custom/production`：四项定制的组织发布分支。
- `migration/four-extensions`：此次移植和验收分支。

不要强推覆盖现有 `production`。实施时按新仓库实际 AGENTS/分支保护调整规则，旧站开发规范也需更新为新分支模型，并移除已废弃的本地工具章节。本次仅记录方案，不修改任何远端配置，不推送代码。

建议提交按模块拆分：基线与开发规范、图片工作台、首页、教程、充值提醒、集成与退出路由、测试与发布配置。每个提交都可独立审查。避免直接 cherry-pick 含有其他功能的混合提交。

镜像建议使用 `ghcr.io/baibaiai001/sub2api:<明确版本>-custom.<序号>`（实际包权限和组织发布配置实施前核实），同时记录源提交和 digest。组织仓库需要检查 Actions 是否启用、GHCR 写权限、Release 工作流、上游遗留 DockerHub/通知配置；不要复制作者的通知目标。生产部署固定自建镜像 digest，不使用 `latest`。

## 6. 上线前必须解决的风险

### 6.1 历史打票设置会被重新读取

只读评估发现当前数据库仍保存 `openai_codex_ticket_enabled=true` 和旧采集代理配置。当前版本不再使用的键，fork 会再次读取；卸载 STATE 插件并不等于关闭 fork 内置采集。

恢复副本上先显式关闭该开关并清除/隔离旧采集出口引用，核对有效配置优先级。正式切换时在停写和完整备份后，单独记录并处理同名设置。Prism、自动重认证、质量巡检自动动作、请求捕获等新功能初期保持关闭或未配置，不让复制的数据意外触发外呼、账号停调、BPS 切换或额外费用。

本方案不包含代理密码、Token 或数据库凭据；密钥保持在现有安全配置/备份中。

### 6.2 数据库与回滚

30 条待补跑迁移主要新增表、字段、约束和索引，但 ALTER TABLE 和建索引仍可能等待锁。首次迁移时长只能通过副本实测确定，不承诺零停机。教程迁移原样保留后，重算最终清单与 checksum。

回退镜像不会撤销数据库迁移、设置变化或账号自动操作。必须在副本验证旧镜像能否读取迁移后的数据库；不兼容时采用升级前数据库及应用数据恢复。全量恢复会丢失备份后写入的交易和用量，正式窗口应停写并记录账务截点，不能带流量盲目恢复。

### 6.3 核心行为与外部服务

fork 发布说明明确没有同步部分原作者特性，例如在途余额预占和 Claude 原生额度查询/兑换。这些变化即使不迁入旧定制也会发生，需重点验证并发余额、结算、模型路由、SSE/WebSocket 和账号错误处理。

保留当前 PostgreSQL 18、Redis 8、数据卷、Nginx、域名证书和仅本机暴露的应用端口。不要覆盖整份 Compose，不重建数据库/Redis，不执行 `down -v`。保留 JWT、TOTP、插件及应用加密所需密钥、时区和可信代理配置。原生 fork 镜像中的可选 Worker/浏览器/Mihomo 并非四个保留模块的上线前提。

## 7. 分阶段实施步骤

1. **冻结基线**：重新记录线上镜像、提交、Compose、迁移 checksum、服务和扩展配置摘要；记录四项功能截图/行为作为验收基准。新组织仓库以明确提交为基线。
2. **移植四模块**：在独立 checkout 开发，最小化核心集成；清理首页死链接、旧侧边栏入口和旧 Feature Flag 引用；生成 Wire/必要代码；保留实际充值倍率。
3. **静态和自动验证**：后端相关单元/集成/权限契约检查，前端类型、定向 lint、相关单测和生产构建，迁移 checksum 检查。检查新增 JS、配置、镜像层不含凭据。
4. **隔离演练**：在独立 PostgreSQL、Redis 和应用数据副本上恢复备份，只绑定本机测试端口，不共享线上缓存或挂载线上可写目录。启动前阻断外部网络并关闭邮件、支付通知、定时测试、采集、账号刷新等会产生副作用的任务；必要请求使用 mock。验证全部迁移、四模块和核心数据；记录耗时与资源峰值。
5. **回滚演练**：先在副本测试旧镜像兼容性，再演练恢复原始数据库和应用数据。记录恢复时间、数据对账结果和明确命令，形成最终发布操作单。
6. **发布候选镜像**：四模块验收通过后，从确定提交构建组织镜像，记录 digest、架构、版本和验证结果。推送/正式上线属于后续实施动作，本次不执行。
7. **正式维护窗口**：停止新写请求，等在途请求结束；暂停可能写数据库的外部任务；备份数据库、`data`、部署文件、所需密钥及旧镜像引用。处理历史开关后只重建应用容器，执行迁移，完成验证再恢复流量。
8. **观察与归档**：观察一个完整业务高峰及一个定时任务周期，检查错误率、响应时间、扣费、账号暂停和磁盘增长；确认后结束迁移，历史扩展数据清理另行安排。

## 8. 验收标准

| 范围 | 必须通过 |
| --- | --- |
| 图片工作台 | 登录与用户隔离、分组/Key 权限、文生图/图生图、提示词优化、错误提示、下载、配置继承；真实少量调用仅在后续实施明确允许时进行 |
| 首页 | 当前品牌和布局可用，移动端/深浅色正常，所有内部链接可达，无旧广场和工具启动依赖 |
| 教程 | 原有视频与封面展示、管理员上传与编辑、公开权限、播放计数、文档链接正常 |
| 充值提醒 | 客服/人工优惠说明保留，展示倍率与后端报价一致；支付/赠金/订阅流程不被组件改变，无双重优惠 |
| 退出功能 | 自定义模型广场、Helper、旧图库入口和 API 不再提供原功能；无旧任务启动、无 STATE 脚本注入；已撤旧路径返回明确 404/410，避免 SPA 假 200 |
| 核心业务 | 用户/账号/Key/余额/订阅/订单数量和抽样值一致，鉴权、SSE、WebSocket、正常计费与错误处理通过 |
| 运维 | 应用及依赖健康，迁移无错误，无异常外呼和停调，日志保留策略明确，备份和回滚演练完成 |
